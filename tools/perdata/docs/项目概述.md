### **项目：内容生成引擎 (Content Generation Engine)**

**项目类型**: 离线数据预处理工具集
**核心目标**: 为“奥赛生物智能学习伴侣”线上平台，自动化生成并注入所有基础的知识内容，包括知识图谱和练习题库。

#### **1. 项目定位与哲学**

*   **LLM 作为核心驱动力 (LLM-Native)**: 我们不再采用传统的、多步骤的 NLP 技术栈（如NER、关系抽取等）。本项目将直接利用 **大型语言模型（LLM）** 的强大上下文理解、推理和生成能力，作为数据生成的唯一核心引擎。
*   **Prompt 工程即核心工程**: 本项目的技术关键在于设计、测试和优化一系列高效、稳定、可控的 **Prompts**，以指导 LLM 精准地完成我们的任务。
*   **人机协同 (Human-in-the-Loop)**: AI 生成的内容必须经过人工审核。本项目产出的数据是“初稿”，最终需要由生物学领域的专家进行校验和修订，以确保其绝对的准确性和教学价值。
*   **独立项目，独立运作**: 这是一个与主站线上服务分离的独立项目，在本机或受控的开发环境中运行，其产出是主站的数据源。

#### **2. 技术选型**

*   **核心 AI 模型**: **Google Gemini 2.5 Flash**
    *   **选型理由**:
        1.  **超长上下文窗口 (Long Context Window)**: 这是最关键的特性。我们可以将整个章节甚至更多的内容一次性喂给模型，使其能够在极其广阔的上下文中进行推理，从而生成更准确、更宏观的知识图谱和题目。
        2.  **高性能与低成本**: "Flash" 版本在保持极高质量的同时，提供了更快的响应速度和更低的成本，非常适合需要进行大量批处理调用的数据生成任务。
        3.  **多模态能力**: Gemini 的多模态能力为未来处理教材中的图表提供了可能。
*   **运行环境与语言**: **Python**
    *   **理由**: 拥有 Google AI Python SDK，与 Gemini API 集成最方便。同时具备强大的文件处理和数据操作能力。
*   **数据输出目标**:
    *   **图数据库**: Neo4j AuraDB
    *   **关系型数据库**: Cloudflare D1

#### **3. 核心功能与工作流**

##### **功能一：知识图谱生成 (Graph Generation)**

*   **输入**: *Campbell Biology* 教材的一个或多个章节的纯文本内容。
*   **工作流**:
    1.  **准备输入**: 脚本读取指定章节的文本内容。
    2.  **构建 Prompt**: 脚本构建一个精心设计的 Prompt。这个 Prompt 会指示 Gemini 2.5 Flash：
        *   "你是一名顶尖的生物学专家和数据架构师。"
        *   "请仔细阅读以下《坎贝尔生物学》的章节内容。"
        *   "你的任务是识别出本章节所有的核心生物学概念，并将它们作为**节点**。"
        *   "同时，识别出这些概念之间的主要关系（例如：‘属于’、‘包含’、‘调控’、‘产生’、‘位于’等），并将它们作为**关系**。"
        *   "请以指定的 JSON 格式输出结果，格式为 `{ "nodes": [...], "relationships": [...] }`。每个节点应包含 `id` 和 `name` 属性，每个关系应包含 `source_id`, `target_id` 和 `type` 属性。"
    3.  **调用 LLM**: 脚本将包含“章节文本”和“指令”的完整 Prompt 发送给 Gemini 2.5 Flash API。
    4.  **解析与转换**: 脚本接收 LLM 返回的 JSON 数据。
    5.  **数据注入**: 脚本将解析后的 JSON 数据转换为 Cypher 查询语句，并连接到 Neo4j AuraDB，执行注入操作。

##### **功能二：练习题库生成 (Question Generation)**

*   **输入**: *Campbell Biology* 教材中某个特定页面的 PDF 公开 URL。
*   **工作流**:
    1.  **准备输入**: 脚本根据用户提供的页码，构建对应的 PDF 文件 URL。
    2.  **构建 Prompt**: 脚本为题目生成任务构建 Prompt，指示 Gemini API：
        *   "你是一位经验丰富的生物奥林匹克竞赛出题专家。"
        *   "请根据以下提供的教材页面内容，生成 5 道高质量的单项或多项选择题。"
        *   "题目必须紧扣原文内容，考察学生的理解和记忆能力。"
        *   "每道题都需要提供：题干、多个选项（包含一个或多个正确答案）、正确答案的标识，以及对正确答案的简要解析。"
        *   "请以指定的 JSON 数组格式输出结果，每个对象包含 `question_text`, `options`, `correct_answers`, `explanation` 字段。"
    3.  **调用 LLM**: 脚本向 Gemini API 发送请求。
    4.  **解析与暂存**: 脚本接收并解析返回的题目 JSON 数据，并将其保存到 `output/generated_questions/` 目录下的一个 `page_XXX.json` 文件中。
    5.  **人工审核**: 生物学专家从 `generated_questions` 目录中获取生成的 JSON 文件，进行审查和修改。完成审核后，将文件移动到 `output/processed_questions/` 目录。
    6.  **数据注入**: 内容管理员运行 `seed-questions` 命令。脚本会读取 `processed_questions` 目录下的所有 JSON 文件，将它们转换为 SQL INSERT 语句，并注入到 Cloudflare D1 的 `Questions` 表中。

#### **4. 项目产出**

*   **一系列 Python 脚本**: 例如 `run_graph_generation.py`, `run_question_generation.py`, `approve_questions.py`, `seed_databases.py`。
*   **一个 Prompt 库**: 一个专门存放和管理所有核心 Prompt 的目录，这是本项目的“智慧核心”。
*   **注入到生产数据库中的高质量基础数据**: 这是本项目的最终交付物。

**总结**:

这个更新后的文档明确了预处理项目的**现代化、LLM驱动**的本质。它不再依赖复杂的传统 NLP 管道，而是将核心竞争力放在了**与先进 LLM 的高效交互**上。这使得项目目标更聚焦，技术实现路径更直接，并且能够充分利用 Gemini 2.5 Flash 的强大能力，有望生成比传统方法更具深度和广度的内容。
